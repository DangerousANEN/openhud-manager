# Руководство оператора PROTOKOL HUD Manager (CS2 Broadcast Suite)

Полное практическое руководство по развёртыванию, эксплуатации и сопровождению турнирного эфирного комплекса **PROTOKOL HUD Manager** (версия 0.1.0 / Tauri 2 / Rust Axum / Vue 3 / SQLite).

---

## 1. Честный статус готовности (версия 0.1.0)

Перед началом работы операторам и техникам трансляций необходимо учитывать реальный статус компонентов системы:

- **Ядро приложения и API:** Axum 0.7 + Tokio + SQLite (WAL-режим) на порту `1349` (HTTP/WebSocket), модули нормализации GSI (`src-tauri/src/gsi.rs`), парсинг SteamID64, оружия, патронов, киллов раунда, роутинг оверлеев и управление камерами полностью функциональны и подтверждены сьютами тестов (`cargo test --lib`, `backend_e2e.py`, `camera_e2e.py`).
- **HUD-паки:** Три независимых пака (`fennec-cyber`, `fennec-broadcast`, `fennec-championship`) протестированы на 720p, 1080p, 1440p, поддерживают живое переключение веб-камер, формулу радара Eidetic и защиту от перекрытий.
- **Статус Windows-инсталлятора (MSI / EXE):** Сборка инсталлятора через `tauri build` формирует `.msi` и `.exe`, однако готовый Windows-инсталлятор **ещё не проходил полное боевое сквозное тестирование на чистых Windows-системах** (без предустановленных зависимостей WebView2 / VC++ Redistributable, а также пока не имеет EV-сертификата цифровой подписи SmartScreen). 
- **Рекомендованный запуск в production:** Запуск собранного бинарника `protokol-hud-manager.exe` с предварительной проверкой доступности порта и зависимостей, либо запуск через репозиторий (`npm run tauri dev` / `npm run tauri build`).

## 2. Установка и запуск

### 2.1. Системные требования
- **ОС:** Windows 10 / 11 (64-bit)
- **Среда выполнения:** Microsoft Edge WebView2 Evergreen Runtime (штатно в Windows 10/11)
- **Порты:** Свободный локальный порт `1349` (по умолчанию; при занятости бэкенд перебирает порты до `1359`)
- **ПО для трансляции:** OBS Studio версии 28.0+ (рекомендуется 30+) с аппаратным ускорением браузера
- **Игра:** Counter-Strike 2 (клиент наблюдателя / GOTV или выделенный сервер с поддержкой GSI)

### 2.2. Запуск из бинарника
1. Запустите `protokol-hud-manager.exe`.
2. При первом старте приложение автоматически:
   - Создаёт базу данных SQLite: `%APPDATA%\PROTOKOL HUD\protokol.db` (с таблицами `teams`, `players`, `matches`, `tournaments`, `sponsors`, `settings`, `servers`, `hud_layouts`, `cameras`).
   - Инициализирует директорию оверлеев: `%APPDATA%\PROTOKOL HUD\overlays\` (переносит паки при наличии данных из `%APPDATA%\OpenHUD\overlays\`).
   - Запускает HTTP и WebSocket сервер на `http://127.0.0.1:1349`.
3. Если SmartScreen выдаст предупреждение о неизвестном издателе, выберите: **«Подробнее» → «Выполнить в любом случае»**.

### 2.3. Сборка из исходного кода
Для сборки требуется: Node.js 18+, Rust (stable toolchain) и Visual Studio C++ Build Tools.
```bash
git clone https://github.com/DangerousANEN/openhud-manager.git
cd openhud-manager
npm install

# Режим разработки с hot-reload UI:
npm run tauri dev

# Релизная компиляция:
npm run tauri build
```
Скомпилированный бинарник будет находиться в каталоге `src-tauri/target/release/protokol-hud-manager.exe` (или в настроенном cargo target-dir).

## 3. Каталоги данных и хранилище

| Сущность | Физический путь в ОС Windows | Назначение |
|---|---|---|
| **Рабочая база SQLite** | `%APPDATA%\PROTOKOL HUD\protokol.db` | Настройки, турниры, команды, игроки, камеры, макеты |
| **Журналы WAL/SHM** | `%APPDATA%\PROTOKOL HUD\protokol.db-wal`, `...-shm` | Транзакционные журналы SQLite WAL |
| **Раздаваемые оверлеи** | `%APPDATA%\PROTOKOL HUD\overlays\` | Папки HUD-паков, доступные по HTTP `/overlay/<pack>/` |
| **Легаси-каталог (миграция)** | `%APPDATA%\OpenHUD\overlays\` | Автоматически синхронизируется в `PROTOKOL HUD` при старте |
| **Общие библиотеки** | `%APPDATA%\PROTOKOL HUD\dependencies\` | Клиентские зависимости cs-hud |

> **Внимание:** Папка `overlays\` в корне git-репозитория служит источником сборщика и шаблонов. Сервер в рантайме раздаёт оверлеи **только** из `%APPDATA%\PROTOKOL HUD\overlays\`. Любые прямые правки CSS/JS для проверки в OBS следует вносить в `%APPDATA%` либо переустанавливать пак через приложение.

## 4. Подключение CS2 к менеджеру (Game State Integration)

### 4.1. Где размещается конфигурационный файл
Конфиг GSI помещается строго в подкаталог `cfg` Counter-Strike 2:
```text
<Steam_Library>\steamapps\common\Counter-Strike Global Offensive\game\csgo\cfg\gamestate_integration_protokol.cfg
```
*Типовые стандартные пути в Windows:*
- `C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive\game\csgo\cfg\`
- `D:\SteamLibrary\steamapps\common\Counter-Strike Global Offensive\game\csgo\cfg\`

Имя файла **обязано** начинаться с префикса `gamestate_integration_` и иметь расширение `.cfg`.

### 4.2. Автоматическая установка из GUI
1. В приложении откройте вкладку **«Настройки»** (раздел «Система»).
2. В блоке «CS2 Game State Integration» приложение автоматически выполнит поиск папки CS2 на дисках C:..Z:.
3. Если путь определился (`CS2 найдена: ...`), нажмите **«Установить GSI cfg в CS2»**.
4. Если игра установлена в нестандартную папку, выберите её через кнопку с иконкой папки и затем нажмите кнопку установки.

### 4.3. Ручная настройка и содержимое конфига
Если вы настраиваете машину вручную или используете выделенный сервер обсервера, создайте файл `gamestate_integration_protokol.cfg` со следующим содержимым:

```vdf
"PROTOKOL HUD Manager"
{
    "uri" "http://127.0.0.1:1349/api/gsi"
    "timeout" "5.0"
    "buffer" "0.1"
    "throttle" "0.1"
    "heartbeat" "10.0"
    "auth"
    {
        "token" "ВАШ_ТОКЕН_ИЗ_НАСТРОЕК"
    }
    "data"
    {
        "provider"               "1"
        "map"                    "1"
        "round"                  "1"
        "player_id"              "1"
        "player_state"           "1"
        "player_weapons"         "1"
        "player_match_stats"     "1"
        "allplayers_id"          "1"
        "allplayers_state"       "1"
        "allplayers_match_stats" "1"
        "allplayers_weapons"     "1"
        "allplayers_position"    "1"
        "phase_countdowns"       "1"
        "bomb"                   "1"
    }
}
```

### 4.4. Токен авторизации (`auth.token`)
- Бэкенд PROTOKOL HUD Manager генерирует UUID v4 токен при первом запуске и сохраняет его в таблице `settings` (`gsi_token`).
- Эндпоинт `POST /api/gsi` сверяет поле `payload.auth.token`. При несоответствии бэкенд возвращает `401 Unauthorized`.
- Скопируйте актуальный токен на странице «Настройки» перед ручным созданием файла.

### 4.5. Разница: Клиент игрока vs Клиент наблюдателя (GOTV / Observer) vs Игровой сервер
Это важнейшее техническое требование Valve к GSI:
- **Обычный клиент игрока (POV-игрок):** Движок CS2 из соображений защиты от читов **не отправляет** блоки `allplayers_*` на обычный клиент. Если запустить GSI на машине обычного игрока, оверлей покажет только одного игрока, а радар и вторая команда останутся пустыми.
- **Клиент официального наблюдателя (Spectator / GOTV):** Игрок, зашедший на сервер в слот спектатора (`spectator`) или смотрящий GOTV-эфир без задержки, получает от движка полный дамп `allplayers_*` (HP, броню, деньги, координаты, оружие всех 10 игроков, таймер бомбы).
- **Прямой GSI с выделенного сервера (Dedicated Server):** Выделенный сервер CS2 также может отправлять GSI на порт менеджера, если на сервере прописан данный cfg. Но для локального обсервера рекомендуется схема «CS2 обсервера → PROTOKOL HUD Manager».
- **Сетевое размещение:** Если CS2 спектатора запущен на отдельном ПК от эфирного ПК с менеджером, укажите в URI сетевой IP эфирного ПК: `"uri" "http://192.168.1.50:1349/api/gsi"`, и откройте порт `1349 TCP` во входящих правилах Брандмауэра Windows на эфирном ПК.

## 5. Порядок запуска трансляции (Launch Ordering)

Во избежание рассинхронизации WebSocket и пустых фреймов строго соблюдайте порядок запуска:

1. **Шаг 1: Запуск PROTOKOL HUD Manager.**
   - Убедитесь, что сервер успешно стартовал на порту `1349`.
   - В менеджере перейдите на страницу «Live» (индикатор соединения в ожидании).
2. **Шаг 2: Запуск OBS Studio.**
   - Сцена с Browser Source подключится к локальному HTTP-серверу менеджера и поднимет постоянный WebSocket-канал `/ws`.
3. **Шаг 3: Запуск Counter-Strike 2 (Клиент наблюдателя).**
   - CS2 считывает GSI-конфиги **только в момент холодного запуска игры**. Если конфиг был установлен при уже открытой CS2, игру необходимо перезапустить.
4. **Шаг 4: Подключение к матчу.**
   - Зайдите на сервер в слот наблюдателя или запустите GOTV-демо.
   - Как только игра отправит первый HTTP POST на `/api/gsi`, на странице «Live» активируется зелёный статус «CS2 на связи», и HUD в OBS мгновенно заполнится данными.

## 6. Настройка трансляции в OBS Studio (vMix / Streaming Software)

### 6.1. Добавление Browser Source
1. В OBS Studio в списке источников нажмите **«+» → «Браузер» (Browser)**.
2. Задайте понятное имя, например: `HUD - PROTOKOL Broadcast`.
3. Укажите параметры:
   - **URL:** `http://127.0.0.1:1349/overlay/fennec-broadcast/index.html` (или выбранный стиль)
   - **Ширина (Width):** `1920`
   - **Высота (Height):** `1080`
   - **Частота кадров (FPS):** `60`
   - **Пользовательский CSS (Custom CSS):** Оставьте поле **пустым** (не добавляйте сторонние стили фона).
4. **Критические флаги источника:**
   - ❌ **СНИМИТЕ флаг:** *«Завершать захват, когда источник невидим» (Shutdown source when not visible)*.
     *Почему:* Если флаг активен, при переключении на камеру комментаторов или паузу OBS разорвёт WebSocket-соединение. При возвращении на игровую сцену HUD будет заново инициализироваться с задержкой в 1–2 секунды.
   - ❌ **СНИМИТЕ флаг:** *«Перезагружать браузер, когда сцена становится активной» (Refresh browser when scene becomes active)*.
   - ✔️ **ВКЛЮЧИТЕ флаг:** *«Управление звуком через OBS» (Control audio via OBS)* — если планируется вывод звуков или медиапотоков через браузер.
   - ✔️ В настройках OBS: *«Расширенные» → «Включить аппаратное ускорение браузера»* должно быть **включено**.

### 6.2. Прозрачность фона и сброс кэша
- Все оверлеи PROTOKOL скомпонованы с `background: transparent`. Движок CEF (Chromium Embedded Framework) в OBS отображает оверлей прозрачным поверх источника «Захват игры» (CS2).
- **Если оверлей завис или обновлялись файлы стилей:** Правый клик по источнику в OBS → **«Обновить кэш текущей страницы» (Refresh cache of current page)**.

### 6.3. URL-адреса штатных HUD-паков
Менеджер включает 3 полностью независимых турнирных HUD (собственный DOM, табличные либо колоночные макеты, нулевые конфликты стилей):

| Стиль HUD | URL в OBS Browser Source | Визуальная специфика |
|---|---|---|
| **PROTOKOL Cyber** | `http://127.0.0.1:1349/overlay/fennec-cyber/index.html` | Вертикальные HP-колонны (скайлайн), неон `#00f0ff`/`#ff007f`, скошенные карточки |
| **PROTOKOL Broadcast** | `http://127.0.0.1:1349/overlay/fennec-broadcast/index.html` | Телевизионная таблица со строками статистики, TV scorebug, синий/янтарный стиль |
| **PROTOKOL Championship** | `http://127.0.0.1:1349/overlay/fennec-championship/index.html` | Золото и оникс, радиальные SVG-индикаторы HP, герб мейджора |

## 7. Веб-камеры игроков (SteamID64, VDO.Ninja, Direct Video)

PROTOKOL HUD Manager реализует встроенную систему динамического переключения видеопотоков игроков в нижней карточке фокуса (Focused Player Card) без создания громоздких сцен с 10 отдельными слоями в OBS.

### 7.1. Как это работает в архитектуре
1. Обсервер в CS2 переключается на игрока (клавиши 1–0 или клик мыши).
2. CS2 передаёт поле `player.steamid` (SteamID64) в GSI-пакете.
3. Библиотека `_core/core.js` сопоставляет SteamID64 со списком настроенных камер из SQLite (доступных через `GET /api/cameras`).
4. При совпадении оверлей монтирует тег `<video>` или `<iframe>` прямо в контейнер веб-камеры.
5. **Важно:** Ядро PROTOKOL использует кеширование слота (`cameraSlots`). Пока спектатор остаётся на одном игроке, тики GSI **не пересоздают DOM-элемент видео** и не перезапускают поток.

### 7.2. Добавление веб-камеры в интерфейсе
1. Перейдите на страницу **«Веб-камеры»** (раздел «Продакшн»).
2. Нажмите **«Добавить камеру»**:
   - **SteamID64 игрока:** 17-значный идентификатор Steam (например, `76561198012345678`).
   - **Тип источника:**
     - `Прямое видео (HTML5 video)` — прямые ссылки на `.mp4`, `.webm`, стриминговые RTSP/HLS/WebRTC шлюзы.
     - `Встраиваемый фрейм (iframe / VDO.Ninja)` — ссылки для встраивания WebRTC.
   - **URL источника:** Валидный URL, начинающийся с `http://` или `https://`.
3. Нажмите **«Сохранить»**. Настройки камер мгновенно рассылаются во все открытые оверлеи через WebSocket-событие `cameras_changed`.

### 7.3. Интеграция с VDO.Ninja (рекомендованный стандарт киберспорта)
При использовании VDO.Ninja используйте **View-ссылки**, предназначенные для плеера:
- Пример правильного URL: `https://vdo.ninja/?view=ROOM_OR_STREAM_ID`
- **Обязательные параметры:**
  - `&cleanoutput` — убирает элементы управления интерфейса VDO.Ninja.
  - `&transparent` — делает фон страницы прозрачным.
  - Параметр `&muted` автоматически принудительно выставляется ядром PROTOKOL для исключения эха в эфире.
- ❌ **Запрещено:** Вставлять ссылки на комнату режиссёра (`vdo.ninja/?director=...`) или ссылки с паролями/токенами в формате `http://user:pass@host/` (такие URL блокируются валидатором безопасности бэкенда).

### 7.4. Режим Dual-Mode: Live-камеры vs 2D-аватары агентов
Каждый HUD поддерживает автоматическое замещение:
- Если для наблюдаемого игрока камера **не настроена или отключена** — в окне камеры отображается 2D-рендер бодишота активного агента CS2 (спецназовец SAS для CT или повстанец для T), либо аватар игрока из карточки каталога.
- Если оператор хочет использовать традиционный захват физической веб-камеры отдельным слоем OBS, расположенным **под** оверлеем:
  - Добавьте в URL Browser Source параметр: `?cam=live` (например: `http://127.0.0.1:1349/overlay/fennec-broadcast/index.html?cam=live`).
  - В этом режиме фоновые 3D/2D-аватары агентов скрываются (`display: none`), внутренность окна становится прозрачной, и открывается дизайнерская рамка с бейджем `LIVE CAM`.

## 8. Добавление и управление HUD-паками

### 8.1. Формат и структура папки HUD-пака
Каждый пак представляет собой изолированную папку внутри каталога `%APPDATA%\PROTOKOL HUD\overlays\<имя-пака>\`.

Минимально необходимая файловая структура пака:
```text
%APPDATA%\PROTOKOL HUD\overlays\my-custom-hud/
├── index.html        # Главный документ оверлея (точка входа для OBS)
├── hud.js            # Логика рендеринга (подключает window.ProtokolCore)
├── hud.css           # Таблицы стилей и разметка сетки карточек
├── assets/           # Локальные иконки оружия, логотипы, радарные карты
│   └── radars.json   # Константы калибровки радара для карт
```

### 8.2. Требования к разметке и скриптам
- **Подключение общего ядра:** В `index.html` подключается общий скрипт ядра:
  ```html
  <script src="../_core/core.js"></script>
  <script src="hud.js"></script>
  ```
- **Собственные классы и геометрия:** Пак обязан объявлять свои селекторы и grid-сетку. Никогда не полагайтесь на внешние неявные стили.
- **Относительные пути:** Не используйте абсолютные ссылки `/styles.css` или обращения уровнем выше корня `../../`. Допустимы только локальные пути `assets/...` и путь к ядру `../_core/core.js`.

### 8.3. Безопасный процесс добавления нового пака

#### Способ А: Импорт через ZIP-архив в GUI
1. Запакуйте файлы оверлея в `.zip` (файл `index.html` должен находиться либо в корне архива, либо внутри единственной корневой папки).
2. В приложении перейдите на страницу **«HUD-паки»**.
3. В поле «Импорт пака из ZIP» укажите абсолютный путь к файлу архива и нажмите **«Установить»**.
4. Бэкенд проверит архив на уязвимости (защита от Zip-Slip / Path Traversal), создаст безопасную папку (slug) и распакует файлы.

#### Способ Б: Ручная установка (для разработчиков)
1. Откройте проводник по адресу: `%APPDATA%\PROTOKOL HUD\overlays\`.
2. Создайте новую папку с названием вашего стиля, например: `pgl-major`.
3. Поместите туда `index.html`, `hud.js`, `hud.css` и ассеты.
4. В приложении на странице «HUD-паки» нажмите кнопку **«Обновить»**.
5. Пак появится в списке со значком `NATIVE` и прямой ссылкой для OBS: `http://127.0.0.1:1349/overlay/pgl-major/index.html`.

## 9. Управление матчем, турнирами и OBS WebSocket

### 9.1. Каталог команд и игроков
- Вкладка **«Команды»**: добавление названий, коротких тегов (3–4 символа) и логотипов (рекомендуется прозрачный PNG 512×512).
- Вкладка **«Игроки»**: привязка реальных имён, никнеймов и аватарок. **Важно:** поле «Никнейм» должно в точности совпадать со Steam-ником игрока на сервере. По этому ключу данные GSI сшиваются с карточкой участника в БД.
- Вкладка **«Матчи»**: выбор левой и правой команд, формата серии (bo1, bo3, bo5). Флаг «Текущий матч» активирует трансляцию метаданных команд в оверлеи.

### 9.2. Интеграция с OBS WebSocket (версия v5)
Менеджер умеет напрямую управлять сценами OBS и трансляцией:
1. В OBS Studio: откройте меню **«Сервис» → «Настройки WebSocket-сервера»**.
2. Включите галочку **«Включить сервер WebSocket»** (порт по умолчанию `4455`).
3. Задайте системный пароль или снимите флаг аутентификации.
4. В PROTOKOL HUD Manager перейдите в **«Настройки» → «OBS WebSocket»**, укажите порт и пароль, нажмите **«Подключить OBS»**.
5. На вкладке **«Трансляция»** вы сможете переключать настроенные сцены (Match, Veto, Casters, Replay), запускать стрим и запись по единой кнопке оператора.

## 10. Диагностика и устранение неполадок (Troubleshooting)

### Симптом 1: В оверлее отображается только один игрок, а радар и вторая команда пустые
- **Причина:** CS2 запущена на обычном клиентском аккаунте игрока (POV), а не наблюдателя.
- **Решение:** Перейдите в режим наблюдателя (`spectator`), подключитесь к GOTV-серверу или используйте выделенный сервер матча. Проверьте, что в `cfg` включены блоки `"allplayers_* "1"`.

### Симптом 2: Индикатор на странице «Live» неактивен, данные матча не идут
- **Причина 1:** CS2 не перезапускалась после создания cfg-файла. Перезапустите CS2.
- **Причина 2:** Ошибка в пути к файлу. Конфиг должен лежать строго в `<steamapps>\common\Counter-Strike Global Offensive\game\csgo\cfg\`, а **не** в устаревшей папке `csgo\cfg\` первого CS:GO.
- **Причина 3:** Неверный токен. В файле `gamestate_integration_protokol.cfg` значение `"token"` должно совпадать со значением токена на вкладке «Настройки» менеджера.
- **Причина 4:** Порт `1349` заблокирован другим процессом. Проверьте занятость порта в командной строке:
  ```cmd
  netstat -ano | findstr 1349
  ```

### Симптом 3: В OBS Browser Source чёрный экран или ошибка 404
- **Причина 1:** Неверный путь к оверлею. Правильный шаблон URL: `/overlay/<pack_name>/index.html` (в единственном числе: **overlay**, а не `overlays`).
- **Причина 2:** В папке пака отсутствует файл `index.html`.
- **Причина 3:** Файлы оверлея скопированы в git-репозиторий, но отсутствуют в `%APPDATA%\PROTOKOL HUD\overlays\`.

### Симптом 4: Веб-камера игрока не отображается при наблюдении за ним
- **Причина 1:** SteamID64 в настройках камеры указан с ошибкой (должен содержать 17 цифр).
- **Причина 2:** URL веб-камеры использует неподдерживаемый протокол или содержит логин/пароль (`http://login:pass@...`), что блокируется политикой безопасности.
- **Причина 3:** Для VDO.Ninja не выбран тип `iframe / embed` в настройках камеры.
- **Причина 4:** Видеопоток блокируется заголовками `X-Frame-Options` или CSP удалённого сервера. Проверьте открытие ссылки в обычной вкладке браузера.

### Симптом 5: Радар не показывает точки игроков или они смещены
- **Причина 1:** Игра идёт на неофициальной или кастомной карте мастерской, отсутствующей в `radars.json`.
- **Причина 2:** В оверлее отсутствует файл калибровки `assets/radars.json`.

## 11. Памятка оператора перед прямым эфиром (Checklist)

- [ ] Запущен **PROTOKOL HUD Manager** (проверен зелёный статус порта `1349`).
- [ ] В CS2 обсервера установлен актуальный `gamestate_integration_protokol.cfg`.
- [ ] Запущен **OBS Studio**, проверен предпросмотр сцены с браузерным источником (1920×1080 @ 60 FPS).
- [ ] Проверено, что у браузерного источника в OBS **сняты** флаги закрытия при невидимости и перезагрузки сцены.
- [ ] В менеджере заполнены команды матча (названия, логотипы) и активирован статус текущего матча.
- [ ] Внесены SteamID64 игроков и ссылки на их веб-камеры; проверено тестовое переключение.
- [ ] Выполнен тестовый вход на сервер CS2: подтверждено движение игроков на радаре и корректный учёт счёта раундов.
