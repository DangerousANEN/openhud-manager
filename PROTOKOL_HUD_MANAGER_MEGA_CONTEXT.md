## 1. ИСТОРИЯ, МИССИЯ И ПОЗИЦИОНИРОВАНИЕ ПРОДУКТА

### 1.1. Что такое PROTOKOL HUD Manager?
**PROTOKOL HUD Manager** — это легковесный, сверхбыстрый и независимый турнирный комбайн для проведения киберспортивных трансляций по Counter-Strike 2 (CS2).

Исторически индустрия CS-трансляций держалась на двух столпах:
1. **Lexogrine HUD Manager (LHM)** — монолит на Electron + Node.js + NeDB. Прожорливый (~300–500 МБ RAM), запускающий тяжелый экземпляр Chromium на хосте, подверженный утечкам памяти на длинных турнирных сериях (BO3/BO5).
2. **Eidetic HUD Manager (EideticHM)** — популярная Node.js система с качественными оверлеями (включая легендарный стиль *Fennec*), но требовавшая внешнего рантайма Node.js, сложных скриптов запуска и лишенная единого скомпилированного нативного GUI.

**PROTOKOL HUD Manager** заменяет оба этих решения единым нативным десктопным приложением на базе **Tauri v2 + Rust (Axum, Tokio) + Vue 3 + SQLite**, потребляя всего **30–60 МБ RAM** и стартуя мгновенно.

### 1.2. Сравнительная матрица характеристик

| Параметр | LHM (Lexogrine) | EideticHM | PROTOKOL HUD Manager |
| :--- | :--- | :--- | :--- |
| **Ядро приложения** | Electron (Chromium + Node) | Node.js Server | **Tauri v2 (Rust Core)** |
| **Потребление RAM** | 300–500 MB | 150–250 MB | **30–60 MB** |
| **Размер дистрибутива** | ~220 MB | Зависит от node_modules | **~10–15 MB (один .exe)** |
| **Сетевой сервер** | Express / WS (Node) | Express / Socket.io | **Axum 0.7 + Tokio WS (Rust)** |
| **База данных** | NeDB (JSON-файлы) | Локальные файлы | **SQLite (WAL-mode, транзакции)** |
| **Слой отображения UI**| Bundled Chromium | Браузер пользователя | **Системный WebView2 (Edge)** |
| **Радар CS2** | Стандартный растровый | Растровый квадратный | **Векторный прозрачный неоновый (18 карт)** |
| **Поддержка вебкамер** | Ручная подгонка слоев | Требует хаков стилей | **Встроенные 16:9 фреймы + ?cam=live** |

## 4. СИСТЕМА ВЕБ-КАМЕР (WEBCAM INTEGRATION)

### 4.1. Концепция двух режимов (Dual-Mode)
Каждый из 3 новых стилей оснащен гибридной системой отображения:
1. **Режим по умолчанию (Offline / Без стримера)**:
   В рамке 16:9 отображается высококачественный 3D-рендер бодишота активного агента CS2 (CT или T) с плавным угасанием в нижнюю плашку. Оверлей выглядит целостно и профессионально даже без физических вебкамер игроков.
2. **Режим Live Cam (OBS / vMix)**:
   При передаче параметра `?cam=live` в URL оверлея (или при наложении источника видео):
   - Бодишот агента отключается (`display: none`).
   - Центральное окно рамки становится 100% прозрачным.
   - Вокруг видеопотока из OBS отображается дизайнерская рамка стиля, бейдж активности и плашка с ником игрока, KDA и здоровьем.

### 4.2. Настройка сцены в OBS Studio
1. Добавьте в OBS источник **«Браузер» (Browser Source)**:
   - URL: `http://127.0.0.1:1349/overlay/fennec-championship/index.html?cam=live`
   - Ширина: `1920`
   - Высота: `1080`
   - Частота кадров: `60`
   - Поставьте галочку: *«Завершать захват, когда источник невидим»*.
2. Добавьте источник **«Устройство захвата видео»** (Вебкамера игрока / NDI / vMix):
   - Расположите слой вебкамеры **ПОД** слоем оверлея HUD.
   - Позиционируйте вебкамеру по координатам нижнего блока (по умолчанию центр по горизонтали, отступ снизу 90px, размер 280x157px для 16:9).
   - Оверлей аккуратно накроет края камеры фирменной рамкой стиля!

## 5. CS2 РАДАР: 18 КАРТ И МАТЕМАТИКА КООРДИНАТ

### 5.1. Устранение черного фона (Clean Glowing Outlines)
В стандартных оверлеях радар представляет собой квадратную картинку со спутниковым снимком карты, закрывающую значительную часть игрового обзора.
В PROTOKOL HUD Manager радар переработан:
- Написан специальный алгоритм обработки в Python/Pillow: для 18 официальных карт CS2 извлечены только контурные линии, а темный фон сделан полностью прозрачным (альфа-канал на базе шкалы яркости).
- Карты сохранены в `assets/radar-maps-clean/*.png`.
- В CSS оверлея фон сделан прозрачным (`background: transparent`), а контуры подсвечиваются мягким неоновым свечением (`filter: drop-shadow(0 0 6px rgba(0, 212, 255, 0.4))`).

### 5.2. Официальная база карт (18 карт, 78 конфигураций)
Поддерживаются все официальные и соревновательные карты CS2:
- `de_mirage`, `de_inferno`, `de_nuke`, `de_dust2`, `de_ancient`, `de_anubis`, `de_vertigo`
- `de_overpass`, `de_train`, `de_cache`
- `cs_italy`, `cs_office`
- `ar_baggage`, `ar_shoots` (включая night-версии)
- Поддержка многоуровневых карт (Multi-level overviews: Nuke верх/низ, Vertigo этажи).

### 5.3. Математическая формула преобразования координат
CS2 передает координаты игрока в 3D мировом пространстве Valve Source Engine (`world_x, world_y, world_z`).

Файл `radars.json` содержит калибровочные константы для каждой карты:
- `pos_x`, `pos_y` — мировые координаты верхнего левого угла карты.
- `scale` — коэффициент масштабирования игрового мира в пиксели овервью (текстуры 1024x1024).

**Формула расчета экранных координат (в процентах от 0% до 100%):**
```
X (%) = ((world_x - pos_x) / scale / 1024) * 100
Y (%) = ((world_y - pos_y) / -scale / 1024) * 100
```

> **Критический урок разработки:** В некоторых устаревших версиях LHM значение `scale` инвертировалось (`1/scale`). В CS2 и Eidetic scale является прямым множителем. Использование инверсии выбрасывало точки за пределы экрана. Формула выше проверена и откалибрована на реальных турнирных матчах.

### 6.2. Ключевые исправления бэкенда в этой версии
1. **Парсинг SteamID наблюдаемого игрока (`gsi.rs`)**:
   - Было: `player.getSteamID` (устаревшее внутреннее поле JavaScript-оберток).
   - Стало: чтение прямого поля CS2 Valve GSI `player.steamid` с фолбэком на `getSteamID`. Без этого карточка активного игрока оставалась скрытой.
2. **Передача убийств за раунд (`round_kills`)**:
   - В структуру `PlayerSnap` добавлено поле `round_kills: u32`. Теперь при совершении фрагов на карточке игрока загораются черепа/иконки киллов раунда.
3. **Совместимость с Eidetic порт-мостом (`server.rs`)**:
   - Axum слушает порт `1349`, а также готов обрабатывать входящие GSI-пакеты на порту `31982` с токеном авторизации `58317b69-bbfe-405d-a74c-f1b61b0a6aeb`.
