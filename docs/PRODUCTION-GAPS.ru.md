# Пробелы продакшена CS2-турнира: аудит Protokol HUD Manager

Дата: 2026-09-18. Основано на чтении кода репозитория и прогонах E2E этой сессии.
Формат честный: **уже реализовано** отделяется от **реально отсутствующего**;
пункт считается гэпом, только если в коде его действительно нет.

## Что уже есть (не гэпы — зафиксировать, чтобы не выдумывать заново)

- GSI-приём и WS-широковещание (`gsi.rs`), включая `bomb_state`/`bomb_countdown`
  в универсальном payload (коммит `ead51b8`), connection-статус `<10s` (`gsi.rs:184-188`),
  `seconds_since_update()` для диагностики.
- Прозрачный радар, fallback-агенты CT/T, LIVE-бейдж только при реальном видео,
  вебки по SteamID64 (video/iframe) с авто-переподключением WS и retry `radars.json`
  (`core.js`), 16:9 контейнер над фокус-плашкой.
- Турнирные практики в Broadcast: фазовые метки (BUY TIME/LIVE/ROUND OVER/...),
  форматированный таймер, always-visible alive-счётчик, экономика только на
  freezetime, C4-таймер с заливкой и порогами 20s/10s.
- RCON (`rcon` crate в Cargo.toml), наблюдаемый GSI-токен в БД, E2E-набор
  (clock 10/10, alive 3/3, bomb 4/4, score 3/3, camera 3/3, agent_radar 3/3).

## 7 приоритетных гэпов для реального продакшена

1. **Устойчивость GSI-потока на эфире (P0).** `connected()` считает «живым»
   поток с апдейтом <10s (`gsi.rs:184-188`), но при потере GSI оверлеи продолжают
   показывать ПОСЛЕДНИЙ кадр без предупреждения — зритель не видит проблемы.
   Нужно: в HUD — бейдж «SIGNAL LOST» если `updated_at` старше N секунд
   (клиентский таймер), в Live.vue уже есть `status.connected` — добавить в оверлеи.
   Статус: **реализуется в цикле 1 текущего окна**.
2. **Сериализация перерывов/пауз (P0).** Технические паузы (timeout/pause по
   RCON или GOTV) не имеют выделенного UX: фазовые метки есть, но нет
   фиксации «кто взял паузу, сколько осталось» и счётчика таймаутов команды.
   Данные: `phase_countdowns` + `pause` поля GSI; RCON-команды для запроса паузы.
3. **Матч-контекст в оверлеях (P1).** Счёт карт серии (Bo3: 1-0), названия этапа
   и лучшая карта не отображаются в оверлеях — только раундовый счёт. Данные
   есть в менеджере (matches), не прокидываются в HUD-пакеты.
4. **Пик/бан карт и side-индикатор (P1).** В оверлеях нет отображения выбранной
   карты как «PICK» vs «DECIDER» и текущей стороны команды (CT/T) после смены
   сторон — стандарт Major-трансляций.
5. **Аудио-метрики и replay-хуки (P2).** Нет интеграции для «звук выстрелов на
   камере игрока» и автоматических replay-триггеров (multi-kill, clutch) —
   требует внешнего наблюдателя событий (vJoy/фон. скрипт), в GSI частично есть
   `round_kills`, но без ретроспективного буфера.
6. **Отказоустойчивость OBS-сцены (P1).** Оверлеи переживают рестарт менеджера
   (WS reconnect есть), но при переходе на другой порт/URL OBS-источник ломается
   молча. Нужен: экспорт « OBS-пресета» с текущими URL и авто-подстановкой порта.
7. **Профилирование конфигурации тура (P2).** Настройки HUD (пакет, экономика,
   вебки) не привязаны к матчу: перед следующим матчем оператор вручную
   восстанавливает состояние. Нужен: профиль «match preset» (связка match →
   hud-options → cameras), применяемый одной кнопкой.

## Приоритет внедрения

P0 → немедленно (1, 2); P1 → перед следующим турниром (3, 4, 6); P2 → по мере
развития (5, 7). Пункты 1-2 закрываются в текущем 6-часовом окне; остальные —
в следующих проходах.
